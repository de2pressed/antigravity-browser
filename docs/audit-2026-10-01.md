## Validation checkpoint

31 isolated tests cover fake multi-profile hosts, byte-fragmented socket traffic, socket ownership, disconnects, MCP failures, CLI ID parsing, Chrome worker behavior, cursor scheduling, native framing/ffmpeg failure, installer paths/backups, packaged resources, and schema parity. Tests use temporary sockets/HOME, mocked Chrome APIs, and a temporary clone. They do not mutate logged-in browser tabs.

Live checks, source application, and documentation dry-run results are recorded below after completion. A mock proves command/lifecycle logic, not behavior on every website. No throughput benchmark supports the previous sub-second/100%-speed marketing claims; those claims were removed/qualified.

## Remaining limits and future work

- Ownership is profile-wide, not scoped to individual agents. Bulk cleanup can close another client's created scratch tabs; explicit IDs are safer. Caller/session leases need a coordinated protocol change.
- Chrome extension/browser reload may reset session provenance, snapshots and debugger state. Legacy tabs with uncertain creation provenance are retained rather than bulk-closed.
- Client timeout/disconnect does not cancel queued/executing browser work; retries can duplicate mutations. Requests are not transactional and batches can partially complete. Cancellation/outcome persistence requires a protocol redesign.
- Rich HTML/canvas editor acceptance is application-dependent. Paste-event consumption is not verified cell content/save/formatting. Real Google Sheets behavior is not certified by mocked/local input tests.
- Semantic locators are top-document DOM-oriented; cross-origin iframes, shadow roots, clipped/transformed elements, and occluded duplicate controls need more precise targeting. Snapshot AX nodes are not all click targets.
- Native host frame writes are synchronous and long recording frame/disk usage is not quota-managed. Abrupt process death can leave temporary artifacts. ffmpeg can exceed the 45-second worker finalization budget on slow hardware.
- Unix socket/log defaults live under /tmp. File modes restrict normal access, but this is a trusted local-user automation bridge, not a sandbox isolating malicious local clients.
- Watcher reload can be skipped while recording; rerun reload afterward. Non-JS resources are not deeply validated by hot-reload syntax checks. Source skills are not automatically synced to installed copies.
- Popup connection means native port attached, not daemon reachability or website authentication. Focus emulation is not a guarantee of foreground timer/performance equivalence.
- Installer integration uses fake service commands in tests. A real reinstall was not needed to patch the existing deployment; installed service/native manifest paths must be rechecked if the clone moves.

## Final verification evidence

- 31 isolated regression tests passed on both Node 26.3.0 and Node 22.22.3 (supported floor). All runtime JavaScript and shell syntax checks, JSON parsing, schema equality, skill frontmatter checks, packaged-resource checks, and git diff whitespace checks passed.
- Ten live fixture checks passed independently in the personal and work Chrome profiles: background creation, clear/type with emoji, Space, single plain paste, true double-click, snapshot UID click, stale UID rejection, sequential batching, full-page PNG, and MP4/ffprobe H.264 verification. A fresh personal-profile run after final daemon/extension refresh passed all ten checks again. Final PNG: 2545 × 4055; final H.264: 580 × 924, duration 0.866667s, artifacts /tmp/antigravity-live-check-s8DfQt.
- Both PNGs measured 2545 × 4055. Personal first recording: H.264, 606 × 966, duration 0.866667s. Work recording: H.264, 1920 × 966, duration 1.066667s. Dimensions/durations are observed fixture outputs, not performance benchmarks. Temporary artifact directories: /tmp/antigravity-live-check-Z7ckAK and /tmp/antigravity-live-check-WBHuNP.
- Live checks closed only their created fixture IDs; a filtered tab query found no fixture tabs. The fixture server teardown was tightened to close its owned HTTP connections promptly after the first run. No external page/account actions were performed.
- Daemon was restarted to load backend patches; both extensions were reloaded and both exact profile identities reconnected. No installer rerun, bulk tab cleanup, Git commit, push, or PR was performed. A local ignored node-runtime.sh pins the discovered Node executable for Chrome native launchers.
- The knowledge-network dry-run used a fresh-context documentation-only reviewer. It reconstructed the safe paste-fix, verification, reload and schema-update workflow. Its gaps (external MCP restart and copyable live fixture workflow) were corrected. Network relative links were verified; component statuses distinguish tested runtime from unresolved limits.
- Final review added a watcher regression: invalid JS in one file remains blocked even after another file is edited; all extension JS/manifest syntax is checked before reload. It also added CLI nonzero failure results and a literal --force safety regression.
