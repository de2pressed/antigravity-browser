# Status maintenance

Last updated: 2026-10-01.

Per-component files separate live observations from stable architecture. Global status only links and summarizes. Record dates, scope, exact checks, pending actions, and limitations. Use green/yellow/red/unknown/planned consistently; do not mark a live component green because a mock passed.

Every 2-3 turns, batch changes; at session end update global and affected component status. Review weekly or before a runtime claim: process IDs, connected profiles, paths, and installed skill copies can drift. Source edits, daemon restart, extension reload, and browser verification are different evidence states.
